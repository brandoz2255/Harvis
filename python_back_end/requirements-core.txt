# Harvis backend — CORE.
#
# Everything the backend needs to serve chat, RAG, research, documents,
# workspaces and the API surface. Deliberately free of the torch stack: with
# these packages alone `import main` succeeds and every GPU path degrades to a
# no-op (model_manager's null-torch shim) rather than an ImportError.
#
# In-process speech (Whisper STT, neural/Piper TTS) lives in
# requirements-voice.txt. A core-only deploy does speech in the browser or
# through the `stt` sidecar (HARVIS_STT_PROVIDER=sidecar).
#
# Nothing here may pull torch. If a `pip install -r requirements-core.txt` ever
# lands torch in site-packages, a new dependency dragged it in — find it rather
# than accepting it.

# --- Transitive security floors -------------------------------------------
# Neither of these is imported by Harvis directly; both arrive as dependencies
# and both resolved to versions with published advisories. Pinned here because
# there is nowhere else to say it — remove a line only when its parent stops
# pulling the package.

# Pulled in by newspaper3k (unmaintained since 2020, so it will not raise its own
# floor). 3.10.0 carried eight advisories including GHSA-m4rf-3fr8-xwx3 (CRITICAL,
# JVM argument injection via the Stanford tagger) and an unpickler validation
# bypass allowing remote code execution. 3.10.3 fixes seven of the eight; the
# remaining one (GHSA-8mgp-746c-j5xp, model-artifact path escape) has no fix
# released and is only reachable through the model-download APIs, which Harvis
# does not call.
nltk>=3.10.3

# Pulled in by the http2 extras of httpx/httpcore. CVE-2026-71554: a duplicate
# Host header could facilitate request smuggling. Fixed in 4.4.1.
h2>=4.4.1

# Pulled in by python-jose (via rsa) and by google-auth's pyasn1_modules. The
# floor exists to stop a resolver from satisfying an older python-jose cap by
# walking pyasn1 back to 0.4.x, which carries four HIGH DoS advisories. 0.6.4 is
# the first release clear of all four.
pyasn1>=0.6.4

# Not pinnable: ecdsa (a hard dependency of python-jose) carries CVE-2024-23342,
# a Minerva timing attack on P-256, and upstream has published no fix and does not
# intend to. It is inert here — Harvis signs and verifies with HS256 only
# (ALGORITHM = "HS256"; every jwt.decode passes algorithms=[...] explicitly), so
# no ECDSA operation ever runs. Revisit if an asymmetric JWT algorithm is adopted.
